# 클라우드 왕복 사용 안내

데이터베이스 파일 하나(`.db` 또는 `.db.gz`)를 구글 드라이브·OneDrive·Dropbox 같은 동기화 폴더에 두고 여러 PC에서 번갈아 쓰는 방법과, 그때 앱이 띄우는 경고의 뜻을 적는다. 설계 배경은 `DESIGN.md` D-04·D-10과 4.3절이다.

## 앞서 알아 둘 것

- 앱은 파일을 **자동으로 덮어쓰지 않는다**. 저장은 "저장"(Ctrl+S), "다른 이름으로 저장…", 또는 설정에서 켠 자동 저장으로만 일어난다.
- 앱은 파일을 **자동으로 병합하지 않는다**. 두 PC에서 같은 파일을 동시에 고치면 클라우드 서비스가 "충돌 사본"을 만들거나 한쪽이 다른 쪽을 덮어쓴다. 아래 절차는 그 일이 생기지 않게 하는 순서다.
- 파일에는 `db_id`(파일의 고유 번호), `revision`(저장할 때마다 1씩 오르는 번호), `saved_at`(저장 시각), `saved_by`(저장한 기기 이름)가 들어 있다. 기기 이름은 "설정…"에서 바꿀 수 있다.
- 브라우저는 마지막으로 저장한 `revision`을 기기마다 기억한다(IndexedDB `known_revisions`). 파일을 열 때 이 값과 파일의 `revision`을 비교해 경고를 낸다.

## 절차: PC A에서 저장 → PC B에서 열기

1. **PC A에서 작업하고 저장한다.** 도구 모음의 파일 이름 옆에 ● 표시가 없어질 때까지 "저장"을 누른다. 상태바나 토스트에 "…에 저장했습니다"가 뜬다.
2. **동기화가 끝났는지 확인한다.** 클라우드 클라이언트의 아이콘이 "업로드 중"에서 "최신 상태"로 바뀔 때까지 기다린다. 수백 MB 파일은 저장할 때마다 전체가 다시 올라가므로 시간이 걸린다. 파일이 크면 설정의 "압축 저장(.db.gz)"을 켜면 업로드 양이 준다(텍스트 위주 데이터는 보통 3~5배 줄어든다).
3. **PC A의 탭을 닫는다(또는 다른 파일을 연다).** 같은 파일을 두 PC에서 동시에 열어 두면 두 번째 PC의 변경이 첫 번째 PC의 다음 저장에 덮인다.
4. **PC B에서 동기화가 끝났는지 확인한다.** 클라우드 클라이언트가 파일을 내려받아 "최신 상태"가 될 때까지 기다린다.
5. **PC B에서 파일을 연다.** 경고 없이 열리면 정상이다. 경고가 뜨면 아래 표를 본다.
6. 반대 방향도 같다. PC B에서 저장 → 동기화 완료 확인 → PC B 탭 닫기 → PC A에서 동기화 완료 확인 → 열기.

## 경고 메시지의 뜻

| 메시지 | 뜻 | 권하는 행동 |
|---|---|---|
| **"오래된 파일일 수 있습니다"** (이 기기에서 이 데이터베이스의 revision N을 저장한 적이 있는데, 파일은 revision M입니다) | 이 PC가 더 나중 버전을 저장했는데 지금 파일은 그보다 앞선 버전이다. 보통 이 PC가 저장한 뒤 업로드가 끝나기 전에 다른 PC의 옛 파일이 내려와 덮인 경우, 또는 클라우드가 만든 충돌 사본을 연 경우다 | "취소"를 누르고 클라우드 폴더에서 충돌 사본(`… (충돌)`, `… - PC-이름의 충돌 사본` 같은 이름)이 있는지 본다. 어느 쪽이 최신인지 확실하면 "그대로 열기"로 열고 다른 이름으로 저장한다 |
| **"저장되지 않은 변경 복구"** (이 데이터베이스에 저장되지 않은 변경 N건의 기록이 있습니다) | 지난번 이 PC에서 편집하다가 저장 없이 탭이 닫혔고, 그 변경 기록(저널)이 브라우저에 남아 있다. 파일의 revision이 기록을 시작한 시점과 같아 그대로 적용할 수 있다 | "복구"를 누르면 변경이 다시 적용되고 ● 표시가 생긴다. 확인한 뒤 저장한다. 필요 없으면 "버리기" |
| **"다른 버전 위의 변경 기록"** (저장되지 않은 변경 N건이 revision A 위에서 기록되었지만 파일은 revision B입니다) | 이 PC에 저장 안 된 변경 기록이 있지만, 그 사이 다른 PC가 파일을 저장해 버전이 달라졌다. 기록을 그대로 적용하면 다른 PC의 변경 위에 덮이므로 적용하지 않는다 | "별도 파일로 내보내기"를 누르면 기록이 JSON 파일로 내려온다(어떤 변경이었는지 확인용). 파일을 연 뒤 필요한 부분을 손으로 다시 입력한다 |
| **"다른 탭이 이 데이터베이스를 편집 중이어서 읽기 전용으로 열었습니다"** | 같은 브라우저의 다른 탭이 같은 파일을 쥐고 있다 | 먼저 연 탭에서 작업한다 |
| **"이 파일은 더 새로운 버전의 앱으로 저장되었습니다"** | 다른 PC의 앱이 더 새롭다 | 이 PC의 `jdrdatabase.html`을 같은 버전으로 바꾼다. 그 전까지는 읽기 전용이다 |
| **"파일을 연 뒤 디스크의 원본이 바뀌었습니다"** (데스크톱 앱) | 열어 둔 동안 클라우드가 원본 파일을 교체했다 | "다른 이름으로 저장"으로 지금 작업을 따로 남기고, 두 파일을 비교한다 |
| 배너 **"가져오기는 변경 기록에 남지 않아 …"** / **"변경 기록이 50 MB 한도를 넘어 …"** | 이 시점부터 탭이 닫히면 변경을 복구할 수 없다 | 지금 저장한다 |

## 직전 저장본(백업)

브라우저 모드에서는 파일 선택기로 연 파일에 저장할 때마다 **저장 직전의 파일**을 브라우저 안(IndexedDB)에 1세대 보관한다(파일이 200 MB 이하일 때). 잘못 저장했으면 "설정…" → "직전 저장본" → "새 이름으로 내보내기"로 그 파일을 새 이름으로 꺼낼 수 있다. 열린 데이터베이스는 바뀌지 않는다. 다운로드로 저장하는 브라우저(Firefox·Safari)에서는 다운로드 폴더의 이전 파일이 백업이다. 데스크톱 앱은 원본 옆에 `.bak` 파일을 남긴다.

백업이 만들어지지 않은 저장은 상태바에 "저장 전 백업 생략"으로 남는다(파일이 200 MB를 넘거나 브라우저 저장 공간이 부족할 때). 저장 자체는 됐다.

## 자동 저장

"설정…"의 자동 저장은 기본이 꺼짐이다. 켜면 변경이 생긴 뒤 고른 간격(30초~5분)마다 저장한다. 파일 선택기로 연 정본 파일이 있을 때만 동작하고, 다운로드로 저장하는 브라우저에서는 동작하지 않는다. 클라우드 폴더의 파일에 자동 저장을 켜면 저장할 때마다 업로드가 일어나므로 큰 파일에서는 간격을 길게 두거나 압축 저장을 함께 켠다.

## 권장 사항

- 파일 이름에 PC 이름을 넣지 않는다. 같은 `db_id`를 가진 파일이 여러 개 생기면 어느 것이 최신인지 revision으로만 구분해야 한다.
- 두 PC에서 같은 시간에 편집해야 한다면 파일을 둘로 나누거나("다른 이름으로 저장…"), 한쪽은 읽기만 한다.
- 큰 변경(가져오기, 수만 행 붙여넣기) 뒤에는 바로 저장한다. 그 변경은 저널에 남지 않는다.
